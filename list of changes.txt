Why the Code Allows Multi‑Machine Planning
Tool Availability Not Enforced in Scheduling Logic

The code builds tools_available[p] correctly (defaulting to 1 if blank).

But later, when compatibility (vt_compat) is used to assign parts to machines, there’s no check that the number of machines used ≤ tools_available[p].

In other words, compatibility says “this part can run here,” but the planner doesn’t enforce “this part may
 only run on X machines because only X tools exist.”

Strategic Buffer Mode

In efficiency mode, machines are forced to keep busy. Without a constraint, the same part can be spread across multiple machines even if one machine already covered the indent.

On the floor, tool count = concurrency limit:

If a part has 1 tool, it can only run on 1 machine at a time.

If a part has 6 tools, it can run on up to 6 machines simultaneously, but planners still prefer to minimize tool spread (to reduce COs and simplify flow).

The guiding principle: meet demand with the minimum number of tools/machines possible.

Machine assignment must respect tool count.

Planning must respect minimum tool usage principle (don’t split unnecessarily).

This aligns with shop‑floor reality: one tool = one machine, no matter how many machines are free.
